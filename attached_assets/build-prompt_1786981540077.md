# Build Prompt: "Important Updates" — Daily Task App (with Two-Person Private Chat & Task Decoy Disguise)

Build a full-stack Progressive Web App (PWA) for private communication and task-sharing between exactly two authenticated users. Installable on Android (Chrome) and iOS (Safari "Add to Home Screen"), mobile-first, disguised as a daily task / utility app.

The app's official name, icon, and branding is "Important Updates", presenting itself on the surface as a normal "Daily Task app" (decoy interface). The private chat and reveal-bubble/decryption functionalities are hidden behind a decoy trigger/passcode to ensure discreet usage.

### 3.1 Reveal Bubble — the "fun" chat interaction

This is the core playful feature. It's a client-side animation layered on top of normal messaging — the real message is always delivered and stored as usual; the bubble is just how it's *presented* the moment it arrives.

**How it works:**
1. Sender types a normal message and hits Send, e.g. "I miss you so much"
2. On the sender's screen, a short send animation plays: the text briefly dissolves into floating emojis, then into a few cryptic symbols, before the bubble flies off toward the chat.
3. On the receiver's screen, the message arrives as a **closed bubble** — shown as the emoji/symbol sequence, sitting in the chat like a normal message bubble (not hidden in a notification, not disguised as something else — it's clearly a new chat bubble waiting to be opened).
4. Receiver **taps the bubble** -> it plays a quick reveal animation (symbols -> emojis -> text assembling) -> the bubble expands into a normal chat bubble showing the real message.
5. Once revealed, the message remains visible as plain text for the duration of the active chat session. Once the user closes the app, locks the app, or leaves the chat screen, all messages immediately revert back to their closed/cipher state, requiring a fresh tap to reveal them again when reopened.

**Bubble style options (user picks in Settings, applies per-conversation, both users see the same setting):**
- **Emoji Cipher** — closed bubble shows a short emoji/symbol sequence loosely themed to the message (compulsory decryption/reveal animation on tap)
- **Newspaper Card** — closed bubble renders as a small elegant vintage-style headline card; tapping "unfolds" and decrypts/reveals it (compulsory)

**Important constraints:**
- The reveal bubble / decryption style is not optional; messages must always arrive in a closed/disguised state requiring a tap-to-reveal animation.
- This is a visual reveal/decryption animation, not a security or privacy feature — though the user-facing text may refer to it playfully as "decrypting" or "revealing".
- The real message content is always sent, received, and stored normally (plaintext or normally encrypted-at-rest) — the "hidden" state exists only in the client's rendering, for a fun tap-to-open moment
- Messages revert to their closed/cipher state automatically when the app is closed, locked, or when the user leaves the chat screen.
- Push notification text reads: `"New message from [username]"` (using the specific username of the sender).
- The setting is visible to and editable by both users, never a one-sided hidden toggle

## 5. Decoy Disguise & App Lock

- **App Name & Branding (Compulsory)**: The app is named **"Important Updates"** and is presented to third parties as a simple "Daily Task app" (To-Do List).
- **Decoy UI**: On initial launch, the app must display the Shared To-Do List screen directly, functioning completely as a normal, unsuspicious task manager.
- **Hidden Trigger**: Accessing the private chat requires activating a hidden trigger (e.g., long-pressing the header title "Important Updates", or typing a specific secret command/passcode in the task search bar).
- **App Lock PIN**: Once the hidden trigger is activated, a local PIN lock screen is displayed (separate from the account password).
- PIN hashed locally before any storage/comparison — never stored or transmitted raw
- Configurable auto-lock timeout (immediate / 1 min / 5 min / never) which locks the private chat area and returns the app to the decoy Task view.
- Optional WebAuthn/biometric unlock where supported

## 8. Security Requirements

- All DB queries via ORM/parameterized queries — no raw SQL concatenation
- Every message/task query scoped to the authenticated user's own conversation
- Rate limiting on all write endpoints (messages, tasks, auth)
- Input validation on every endpoint (length limits, type checks)
- If media upload is added later: file size limits + MIME-type validation
- HTTPS enforced in production
- Secure cookie flags (httpOnly, secure, sameSite)
- No secrets/API keys hardcoded in frontend — environment variables only
